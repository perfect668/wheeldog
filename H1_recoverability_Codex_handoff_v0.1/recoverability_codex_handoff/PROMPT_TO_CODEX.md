## 二、第一轮只完成 M0 / EXP0
目标：用 CPU 上可复现的二维 LIPM + 受限辅助执行器，检验“相同当前最大施力能力并不保证相同有限时间恢复能力”的**简化模型现象**。它不是 H1 实验证据，也不是论文创新已经成立。

请完成：
1. Python 项目结构、依赖、README 与 pytest。
2. 人体侧向 LIPM 动力学（m、h、固定 CoP、侧向 x/v）；辅助输入区分命令力与实际力，考虑力限幅、变化率、响应迟滞/感知延迟。
3. 明确的扰动生成（速度脉冲 Δv、外力脉冲）和终端恢复判据。
4. 有约束的有限时间 oracle 恢复求解器；区分 recoverable / infeasible / solver_error，记录所有求解状态；不得提前透视未来扰动给正常控制器。
5. 两类人工抽象执行器配置：F_max 相同，动态响应限制不同。扫描扰动强度/时间窗口，保存真实数据与图像，并说明何时差异不显著。
6. 至少包含零扰动稳定、左右对称、能力单调性、执行约束、求解状态/单位一致性等自动测试。
7. 写 `docs/EXP0_RESULTS.md`，详细描述实际运行结果、参数假设、局限和 Go/No-Go 判断。图表必须有数据文件可重建。

## 三、技术要求
- CPU first: numpy/scipy/cvxpy+OSQP/matplotlib/pytest/pyyaml；不要求 CUDA、4×4090 或 MuJoCo。
- 单一默认入口支持 `--config`、`--output` 和 `--seed`。
- 模型方程、单位、符号、控制延迟与恢复判据写明；无合理依据的参数统一标注 toy model。
- 不生成假数据、不做人为有利的曲线、不声称安全保证。
- 未获取 H1 URDF 之前不要编造机器人关节、尺寸、限位，不提前写真机驱动。
- 若基础推导存在不可行/数值不稳，先排查并如实记录，不要通过偷偷放宽约束获得漂亮结果。

## 四、交付标准
- 干净环境安装后运行 `python -m pytest` 通过。
- 一条命令复现至少一张恢复边界图和若干单条轨迹图。
- 输出配置、种子、求解状态、轨迹数据、指标 CSV/NPZ 和实际依赖版本。
- 给出文件变更清单、commit hash、可复制运行命令、至少一个失败案例与残余风险。
- 对结论分层：模型有效性（测试）、抽象现象（EXP0 数据）、机器人现实性（待 URDF）、方法创新（未验证）。
