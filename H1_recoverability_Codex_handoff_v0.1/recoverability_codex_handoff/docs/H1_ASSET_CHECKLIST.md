# H1 资产/硬件信息接入清单（等用户提供后操作）

## 用户拟提供
1. H1 URDF（完整文件）和被引用的 meshes / textures；若含 ROS package:// 路径，请附 package 结构。
2. 机械臂、夹爪、底盘的完整关节名称及零位定义（如果已知）。
3. 双臂与底盘实际力矩/速度/位移限制（URDF 未必包含真实驱动极限）。
4. 底盘类型（全向/差速等）、轮距、整机重心/质量、底盘制动/抗倾覆数据（如有）。
5. 当前夹爪扶手连接方式和接触力测量手段；没有末端 F/T 传感器必须明确。
6. ROS2/SDK 可用控制接口、低层模式及控制频率（现阶段只记录，不写真机控制代码）。

## Codex 初次接入的任务
- 只读检查：URDF 的 link/joint/mesh、惯性张量、质量、上下限、轴向和坐标约定；输出模型审计报告。
- 使用 Pinocchio（或经测试的等价工具）做 FK、Jacobian、IK，可视化 H1 左右扶手同一世界目标下的多个冗余配置。
- 检查实际有效的底盘自由度及限制，避免误作全向底盘。
- 检查动力学参数完整性；若缺失，则先完成运动学层面的配置对，不随便编造力矩/惯量。
- MuJoCo 能解析 URDF，但载入成功不代表关节执行器、接触和驱动约束正确；必须验证 actuator 配置、mesh、惯性、初始姿态与重力行为。
- 对 10 组随机但可行的配置分别检查关节限位、FK/Jacobian 和碰撞；输出测试结果与截图。

## 严格禁止
- 不把实验性 `100 N`、`0.1 s` 等示例参数标为真实 H1 数据。
- 不直接控制真实机器人做人体实验。
- 不在未经验证时宣称“可托举真人”“具备防跌倒能力”。
