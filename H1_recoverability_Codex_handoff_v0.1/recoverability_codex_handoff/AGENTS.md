# AGENTS.md — Codex 项目工作约束

## 研究原则
1. 优先完成“可证伪的实验”，而不是赶着实现新算法；不把参数调节造成的已知效应包装成创新。
2. 公开文献中的原方法与我们的简化基线要明确区分，例如称 `FORTE-inspired residual-force-margin baseline`，未完整复现不得写 `FORTE reproduced`。
3. 所有物理量明确单位、坐标系、正负号、采样率；每个示意参数标注假设性质，不暗示来源于 H1 或真实患者。
4. 扰动、初始状态、约束、预算对比较方法必须公平。不要人为给“好配置”更快的响应时间后宣称发现了 H1 的物理事实。
5. 对 H1 的关节名称、限位、力矩限制、底盘模型、SDK 和力传感能力，必须读取真实文件或由用户确认，不得猜测。
6. 不得声称“安全保证”“防跌倒能力”“临床适用”；实验验证仅针对明确的模型、扰动集合和误差假设。
7. 不将真实人体作为失衡扰动实验对象；所有初期实验仅仿真或独立保护的机械装置。

## 实现规范
- Python 首选，轻量依赖：numpy、scipy、cvxpy（OSQP）、matplotlib、pytest、pyyaml；尽量可在 CPU 运行。
- 项目代码结构应模块化：人体动力学、辅助执行器、扰动、求解器、实验、可视化和指标相互独立。
- 不做无关的大规模重构；每一阶段独立提交 commit，记录 commit hash。
- 实验配置放 YAML；统一随机种子；结果保留 config/seed/git hash/软件版本与求解状态。
- 代码中保留 `assert`/测试，显式检测求解失败、不可行、超时、NaN、约束违反；不得把求解失败算作成功。
- 图必须可由数据脚本重新生成，导出 PNG/PDF（仅在环境支持和必要时），并存原始 CSV/NPZ。
- 不随意 pin 当前未知的软件版本；给出可工作的版本环境、锁定文件或报告。
- 因无 H1 文件，第一轮不要假装已有可执行的 H1 URDF 接入。可预留接口，不能硬编码假尺寸。

## 方法边界
- Experiment 0 的两种配置是**抽象执行器条件**；其价值仅是核验/演示当前力大小与动态响应不等价。
- 后续需要使用同一 H1 URDF、相同扶手世界位姿、相近当前力裕度，经不同冗余关节/底盘配置，自然产生响应/可达性差异；才能建立机器人相关结论。
- 单次“给定已知扰动存在可行控制序列”（离线 oracle）与“实际因果反馈下可恢复”是两回事，分别报告；预知未来扰动的 oracle 不可当作实际控制器。
- 接触场景、步态变化、真人辅助研究属于后续，不得擅自扩为第一轮范围。

## 每轮结束输出格式
1. 做了什么（具体文件/commit）；2. 实际运行命令和结果；3. 主要数值/图表；4. 失败案例与限制；5. 科学结论及其证据等级；6. 下一步最小任务；7. 需要用户确认的信息。
